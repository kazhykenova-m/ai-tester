# ai-tester: проверка сайтов без платного ИИ

Python + Playwright + Telegram. Основной запуск не использует Gemini, API-ключи ИИ или локальную модель. Существующие `agent.py`/`llm.py` оставлены как старый код для совместимости; бот и CLI их не импортируют. Старые Markdown-сценарии не используются новым движком.

## Mac: Python 3.9, без администратора

Из корня репозитория, с существующим `.venv`:

```sh
.venv/bin/python --version
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
PYTHONPATH=src .venv/bin/python -m ai_tester.bot
```

Если окружения ещё нет: `python3.9 -m venv .venv`. Системный Python, Homebrew и Docker для локального запуска менять/устанавливать не нужно. Браузер устанавливается в пользовательский каталог Playwright. Зависимости закреплены для Python 3.9, включая Playwright 1.60.0 и Pillow 11.3.0. Для LibreSSL в системном Python Mac закреплён urllib3 1.26.20: [urllib3 2 удалил поддержку LibreSSL](https://urllib3.readthedocs.io/en/2.0.0/v2-migration-guide.html). Проверка сертификатов TLS включена.

Создайте `.env` на основе `.env.example`, только если файла ещё нет. Настоящий `.env` эта переделка не изменяет. Gemini-переменные можно оставить: новый запуск их не читает.

| Переменная | Значение |
|---|---|
| TELEGRAM_BOT_TOKEN | Токен BotFather |
| TELEGRAM_ALLOWED_USERS | Числовые ID через запятую; обязательны, только личные чаты |
| BOT_DATA_DIR | `bot-data` |
| TEST_WRITE_HOSTS | Точные имена тестовых доменов через запятую; пусто = блокировка POST/PUT/PATCH/DELETE |
| PROJECT_SCENARIO_DIR | `scenarios/projects` |
| REPORT_RETENTION_DAYS | `7` |

## Для менеджера

`/test` → публичный URL → лендинг / магазин / настроенный сценарий → компьютер / телефон / оба → необязательный PNG → подтверждение → итог и ZIP с HTML, Markdown, JSON и доказательствами.

Общие пресеты делают автоматический аудит открытой страницы. Функциональные проверки без настроенных локаторов перечисляются как пропуски. Для полноценного пути выберите настроенный сценарий проекта. Разработчик задаёт его один раз, менеджер выбирает кнопкой. Вместо свободного текста можно загрузить JSON как документ: бот не притворяется, что понимает текст без ИИ.

`/status` показывает очередь и состояния задач; `/cancel` сбрасывает ввод, отменяет очередь и завершает активный процесс. При перезапуске активная задача помечается прерванной. Очередь SQLite, один изолированный браузерный процесс на задачу, общий лимит 20 задач, максимум одна активная задача пользователя. Сообщения о ходе проверки выдаются по устройствам, без каждого клика. Время задачи ограничено 30 минутами.

## Настройка сценария

Скопируйте и измените `scenarios/projects/landing.json` или `shop.json`. Это примеры, их локаторы нужно адаптировать к сайту. Все JSON в PROJECT_SCENARIO_DIR становятся кнопками после перезапуска бота.

```json
{
  "title": "Лендинг проекта",
  "test_data": ["invalid"],
  "pages": [{
    "url": "/",
    "steps": [
      {"name": "Открыть окно", "action": "click", "locator": {"test_id": "open-modal"}},
      {"name": "Окно открылось", "action": "visible", "optional": false,
       "expected": "Диалог виден", "locator": {"role": "dialog"}},
      {"name": "Невалидный email", "action": "fill", "value": "invalid", "locator": {"label": "Email"}},
      {"name": "Email отклонён", "action": "invalid", "locator": {"label": "Email"}}
    ]
  }]
}
```

Локаторы: `role` (с `name`, по умолчанию exact), `label`, `test_id`, либо `css`. Локатор должен находить один элемент; неоднозначность — ошибка настройки, а не дефект сайта. Нет локатора — пропуск. Отсутствующий элемент по умолчанию пропускается; `optional:false` означает обязательное требование, отсутствие становится функциональным дефектом. После действия добавьте явную проверку ожидаемого результата с `optional:false`.

Действия: `click`, `fill`, `select`, `check`, `press` (Escape/Tab/ArrowLeft/ArrowRight). Проверки: `visible`, `hidden`, `text` (подстрока), `count`, `url`, `invalid` (HTML checkValidity). `value` для fill/select должен находиться в разрешённом `test_data`. Проверки текста/количества/URL используют `value`. `expected` объясняет требование человеку. `pages[].url` задаёт посещаемые страницы относительно введённого URL; допускается публичный абсолютный URL.

Корзина: всем действиям и связанным ожиданиям задайте `effect:"cart"`. Попытка отправки пустой/невалидной формы: `effect:"invalid_form"`; разрешается только если HTML-форма невалидна и текущий домен явно указан в TEST_WRITE_HOSTS. Обычный submit пропускается даже на тестовом домене. Заказы, платежи, реальные заявки не поддерживаются. Guard блокирует также стандартные URL-сегменты checkout/payment/pay/order/purchase/place-order, в том числе на тестовых доменах; нестандартные конечные точки должны быть исключены разработчиком из сценария. Не добавляйте такие переходы в сценарий. Формы с нестандартной JS-валидацией проверяйте через явные ожидания состояния, без отправки.

Пример магазина содержит каталог, поиск, фильтр, товар, вариант, добавление, количество и удаление. Пример лендинга — меню, модалку и валидацию; якоря, кнопки, аккордеоны и слайдеры настраиваются обычными click/visible/text/url. Автоматического понимания функций произвольного сайта нет.

CLI использует тот же сетевой guard, что бот:

```sh
PYTHONPATH=src .venv/bin/python scripts/run_agent.py scenarios/projects/landing.json --url https://example.com --headless --out artifacts/demo
# Добавьте --mobile для телефона
```

Отчёт: `artifacts/demo/desktop/report.html` (либо mobile). Код возврата 1 при дефектах или сбое, 0 при завершённом аудите без подтверждённых дефектов; пропуски необходимо читать в покрытии.

## Figma PNG: без API и токенов

Экспортируйте отдельные desktop/mobile фреймы из Figma в PNG **1×**. Отправляйте как **документ**, не фото. При выборе обоих устройств порядок загрузки: desktop, затем mobile. Бот явно показывает страницу, устройство и область каждого полученного файла. Можно пропустить макеты. Ограничение: 10 МБ на документ, 16 миллионов пикселей на PNG.

Ширина PNG становится viewport в CSS-пикселях; DPR браузера 1. Высота страницы/блока должна совпадать с макетом. Если размеры несовместимы, сравнение пропускается с объяснением. Нет растягивания, автоматического выравнивания или попытки объяснить отличия как неверный padding.

По умолчанию снимается вся страница введённого URL. Разработчик может добавить настройки для устройства в сценарий:

```json
"visual": {
  "desktop": {
    "url": "/",
    "locator": {"test_id": "hero"},
    "threshold": 30,
    "min_area": 100,
    "exclude": [[0, 0, 100, 50]]
  },
  "mobile": {"url": "/", "threshold": 30, "min_area": 100}
}
```

Без locator — весь фрейм, с locator — один блок. Для блока ширина PNG также задаёт viewport: экспортируйте эталон с шириной целевого экрана и блока. `exclude` — прямоугольники [left,top,right,bottom] в координатах сравниваемого изображения; ими исключаются динамические фото, баннеры, даты и счётчики. `threshold` — порог максимальной разницы RGB (0–255); `min_area` — минимальная площадь связной области в пикселях. Связность по четырём соседям. Отчёт содержит долю/число изменённых пикселей и области различий.

Перед снимком ожидаются шрифты и изображения (ограниченное ожидание), отключаются CSS-анимации, переходы и каретка. Проверяется стабильность двух последовательных снимков. Видео/canvas/JS-анимации могут потребовать настройки сайта или исключений. Исходный PNG, скриншот и красные рамки различий входят в архив и HTML. Статус: **«визуальное расхождение — требуется подтверждение»**, отдельно от дефектов.

## Что проверяется и ограничения

На посещённых состояниях фиксируются pageerror, console.error, HTTP 4xx/5xx, failed requests, незагрузившиеся видимые изображения, горизонтальная прокрутка и выход элементов за ширину. Контейнеры с overflow hidden/clip/auto/scroll, невидимые элементы, aria-hidden и SVG исключаются из проверки элементов. `data-audit-ignore` исключает декоративное поддерево. Это эвристика: некоторые намеренные эффекты потребуют ручного разбора. На мобильном устройстве явный visible проверяет ширину и enabled основных настроенных элементов. Размер tap targets и все ошибки доступности не проверяются.

Сторонние сетевые ресурсы выделяются отдельно по точному hostname относительно исходного URL. JS/console не всегда позволяют определить владельца стороннего скрипта. Ошибки, вызванные guard, не считаются сетевыми дефектами. Внутренние/служебные IP, localhost, нестандартные порты, URL с credentials запрещены; проверяются также перенаправления и сторонние запросы. WebSocket и service workers отключены, popup закрывается. TLS не отключается. DNS-проверка приложения не заменяет сетевую изоляцию сервера против DNS rebinding; на сервере ограничьте исходящий доступ к внутренним сетям.

Сайты с изменяющими состояние GET-запросами требуют отдельного тестового окружения: блокировка небезопасных HTTP-методов не гарантирует отсутствие всех побочных эффектов. На тестовых доменах фоновые запросы изменения данных также разрешены. Сценарии задаёт разработчик для контролируемых сайтов.

Подтверждённые функциональные дефекты содержат номер, страницу, устройство, ожидание, факт, шаги и доказательство. Приоритет: high для необработанной JS-ошибки, medium для нарушенного ожидания/сетевого/визуально измеримого нарушения ширины/изображения; синтаксические ошибки исходников high. Это технический приоритет, бизнес-критичность уточняет разработчик. Скриншоты сохраняются для дефектов и визуальных сравнений, успешные клики не записываются. Отдельные разделы: покрытие/пропуски, ограничения, сторонние ресурсы, ошибки тестировщика. Незавершённый запуск не выдаётся за успешный результат с «0 проблем».

## /code

ZIP до 10 МБ, до 1500 записей, распакованный объём до 25 МБ, отдельный проверяемый файл до 1 МБ. Опасные пути и symlink запрещены. Python/JSON проверяются парсерами, JS/PHP — синтаксическими режимами уже установленного Node/PHP; если их нет, проверки пропускаются. Код не запускается, не импортируется, зависимости не устанавливаются. TS/JSX/CSS/HTML не проверяются. Это проверка синтаксиса, не полная проверка чистоты кода.

## Проверки разработки

```sh
.venv/bin/python -m playwright install chromium
PYTHONPATH=src .venv/bin/python -m pytest -q
.venv/bin/ruff check .
```

Тесты поднимают локальный демонстрационный HTTP-сайт и настоящий Chromium. Только тестовый fixture снимает запрет localhost; бот и CLI его сохраняют. Заявки на реальные сайты не отправляются. Покрываются успешный сценарий, дефект, пропуски, блокировка запроса, отмена, незавершённый запуск, сравнение PNG и настоящая сигнатура callback (Route, Request).

## Сервер

Можно использовать виртуальное окружение и процесс-менеджер сервера с теми же переменными. Перенесите настроенные JSON и каталог bot-data (SQLite/отчёты), сохраняйте доступ только разрешённым Telegram ID. Node/PHP нужны лишь для дополнительной проверки синтаксиса.

Docker — дополнительный вариант:

```sh
docker compose up -d --build
docker compose logs -f
```

Compose задаёт BOT_DATA_DIR=/app/bot-data и постоянный том, браузер запускается непривилегированным пользователем. Telegram polling не требует открытого входящего порта. Docker-сборка и реальная доставка файлов Telegram должны быть отдельно проверены в целевом окружении.
